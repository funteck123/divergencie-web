# Changelog

All notable changes to this project will be documented in this file. See [commit-and-tag-version](https://github.com/absolute-version/commit-and-tag-version) for commit guidelines.

## [Unreleased]

### Features

* **mcq-digitizer:** Sample Response coverage extended: A Level Chemistry (official Paper 3 doc + merged iECR for Papers 2/4/5), A Level Computer Science (Papers 1-4), and A Level Mathematics gained a second document for Paper 6 (an older-syllabus "Paper 7" file, confirmed by content -- probability/statistics terms, zero mechanics terms -- to be the same Probability & Statistics 2 component under legacy numbering, not a separate paper). Also added Biology, Business, English General Paper and a second Literature in English paper by downloading real, content-verified documents from the web where nothing existed locally -- one component each for Biology/Business/English General Paper; the rest of those subjects' papers turned up as dead links or login-walled pages this pass and were not force-downloaded. A Level Information Technology has no Example Candidate Responses published anywhere found -- confirmed absent, not missed.

* **mcq-digitizer:** added the per-question "iECR" Sample Response sets (IGCSE Biology and Chemistry, 8 papers) -- these come as one PDF per question rather than one per paper, so a new merge step (`merge_iecr.py`, PyMuPDF) combines them into a single document per component at crawl time, cached and only rebuilt when a source file changes. A Level Physics also has an iECR set but was deliberately left out of this: it only covers a partial subset of questions per paper, and would have duplicated the already-complete official ECR booklet added for that subject last commit.

* **mcq-digitizer:** added Sample Response (Example Candidate Responses) as a component-level yearly resource, same static-document pattern as ZNotes -- 15 real files across IGCSE Physics, IGCSE First Language English, A Level Physics, A Level Mathematics (all 6 papers), A Level English Language and A Level Literature in English. Scoped to v1: the single-PDF-per-paper sets only; IGCSE Biology/Chemistry and A Level Physics also have "iECR" sets (one file per question, 19-21+ files each) left for a follow-up since they need per-question wiring, not this component-level shape.

* **mcq-digitizer (TKT-0269):** Test mode now autosaves the in-progress attempt (chosen answers, flags, written answers, and the timer) in the browser every few seconds and whenever the tab is hidden or closed. If a tab crashes or closes mid-test, reopening Test mode on the same paper offers "Resume it?". The save is cleared on submit or cancel, ignored after 24 hours, and only reused for the same account and paper. It is per browser, not synced across devices.

* **tickets:** Management can now append internal notes to any ticket ("+ Note" under the ticket text in the Tickets tab). Notes are append-only, timestamped, attributed to the author, audit-logged, and never shown to the person who reported the ticket. Backed by a new `note` action on `PATCH /api/tickets`.

* **ops (TKT-0262):** a supervisor (`scripts/ops/question-solver-supervisor.sh`, run as a systemd user unit) now keeps the Question Solver and Syllabus Viewer servers and their Cloudflare tunnels running, restarts any that die, and publishes each new tunnel URL to production config automatically. Before this, a machine reboot left both tools down (production showed "Extraction service unreachable") until someone restarted them by hand and pasted the new URL. Added `PATCH /api/syllabus-config` (Management only) for the URL sync. Live-tested: killing the tunnel or the server recovers in under a minute with no manual step.

* **mcq-digitizer (TKT-0259):** structured-question grading used to give zero for any mark point requiring a table, graph, circuit, ray/force/field, or labelled diagram, since a student can only type plain text -- there was no way to earn that mark at all. The grading system prompt now defines a plain-text notation for each of these (markdown pipe tables; "AXES:"/"LINE:" for graphs; "--"/"//" component chains for circuits; "-->" arrows for ray/force/field diagrams; an indented labelled list for apparatus/biological diagrams) and instructs the grader to mark the structure/labels/values/relationships this notation conveys exactly as it would a real drawn diagram -- only genuinely missing or wrong content still scores zero, not the choice to type instead of draw. Test mode now shows a small collapsible "📐 Answering with a table or diagram?" hint above the answer boxes with this same template, so students know the notation exists before they hit a diagram question and give up on it. Live-verified against a real Venn-diagram shading mark scheme that previously would have scored 0: a text description of which regions to shade now correctly earns full marks.

* **mcq-digitizer (TKT-0256):** structured-question (Theory/Practical/Math) grading now rebuilds a full mark-by-mark ledger, not just correct/incorrect lines -- every individual mark point in the mark scheme gets its own entry showing whether the student earned it, quoting what earned it or exactly what was missing (`markBreakdown`), plus a real full-mark model answer written out line by line (`fullMarkAnswer`) so a student can see exactly what "getting this completely right" looks like. Shown on the Test-mode results screen immediately after grading; also flows through to the account's saved answer history once a small additive DB migration (`ALTER TABLE mcq_question_responses ADD COLUMN mark_breakdown, full_mark_answer`, see `data/tmp/migration_mcq_question_responses_mark_breakdown.sql`) is applied and `scores.mjs` is updated to read/write the two new columns -- not yet done, deliberately deferred pending that migration so existing answer-saving isn't put at risk.

* **mcq-digitizer (TKT-0255):** Test mode and Mistakes mode now offer an opt-in "Show if I'm right after each question" toggle (remembered per-browser via localStorage, off by default so the existing single-submission exam-integrity behavior is unchanged unless a student turns it on). When enabled, each question gets its own "Check answer" button that compares the selected option to that question's already-loaded answer key and shows Correct/Incorrect instantly -- purely client-side, no new server endpoint, no change to the real Submit-quiz scoring or mistake-logging.

* **accounts:** Management can "Log in as" a Student/Teacher/Staff/Parent/Ambassador account without ever seeing or resetting their password, via a short-lived impersonation session with a visible "Stop impersonating" banner and full audit logging. Replaces a proposed change to make stored passwords reversible/viewable again, which would have reopened the plaintext-password-leak incident scrypt hashing was introduced to fix.

* **mcq-digitizer:** Mathematics (and any other subject with no real MCQ paper) can now be practiced question by question in the Question Solver, using the exact same practice-mode UI as the MCQ flow -- a mode-select card, then one card per question with a Question/Answer tab toggle revealing that question's own real mark-scheme crop, no separate stepper or "Open Question Paper" screen.

* **mcq-digitizer (TKT-0242):** structured papers (Theory, Practical, Mathematics -- any non-MCQ component) now have a real Test mode, enabled and exposed to students for the first time -- same "Answer the quiz" flow as MCQ, but the A/B/C/D options are replaced by one combined text box per question for the student's full working. Each question is submitted (and graded) individually rather than all at once at the end -- silently, no score shown until the results screen, same as MCQ never reveals anything mid-quiz either -- and can still be edited and resubmitted afterward; the final "Submit quiz" only has to grade whatever wasn't already submitted (or was edited since). Submitting sends each question's own mark-scheme crop image (never its extracted text) plus the student's answer to Gemini (OpenRouter as fallback) for grading. A question only counts as correct toward the score if it earned FULL marks. The flow itself was already built but had been sitting behind a disabled "coming soon" button, and never recorded a single attempt or mistake even when it did briefly run -- this also wires it into the same progress-tracker/leaderboard/mistake-log tracking MCQ's Test mode already had, none of which existed for structured papers before.

* **mcq-digitizer (TKT-0245):** each worksheet now has "View QP PDF" / "View MS PDF" links -- shown in the paper's mode-select menu and in Practice mode, hidden in Test mode (exam integrity). Clicking streams the real PDF straight from a new same-origin endpoint (`GET /api/mcq/pdf`, proxying `server.mjs`'s existing `downloadDriveFile`) as a forced download, rather than sending the student to a Google Drive view page they may not even have access to.

* **mcq-digitizer (TKT-0246):** Mistakes Mode moved from a generic account-wide link on the home screen into a button next to the Component selector in the main picker, and is now scoped to only the mistakes belonging to papers in that one selected Component -- previously it pulled every unresolved mistake across every subject the student had ever answered a question in, regardless of what they were currently browsing.

* **resources:** a daily automated health check (`GET /api/cron/health-check`, scheduled via `vercel.json`'s new `crons` entry) now pings Question Solver's and Syllabus Viewer's standalone extraction services and emails an alert (via the existing Gmail-API `sendEmail()`) if either is unreachable, and again once it recovers -- both run on Cloudflare quick tunnels with no uptime guarantee and no automatic recovery, and previously a dead tunnel just went unnoticed until someone reported the tool broken. Limited to once/day by the Vercel Hobby plan's cron restrictions (confirmed live, not assumed) -- an outage can run up to ~24h before this fires, accepted as a tradeoff over a paid plan or a second scheduler. Syllabus Viewer's own tunnel URL was also moved out of a hardcoded frontend constant into the same Supabase-backed config Question Solver's URL already used (`GET /api/syllabus-config`), so both a restart AND this health check read from one place, and updating either no longer needs a code push.

### Bug Fixes

* **mcq-digitizer:** removed the M2 document from A Level Mathematics' "Paper 4: Mechanics" Sample Response -- M2 topics (further mechanics: circular motion, rotation) aren't on the current merged Mechanics paper's syllabus, so shipping it would mislead a student about what's examinable. Paper 4 now has only the M1 document, which does match the current syllabus.

* **mcq-digitizer:** fixed a Sample Response mixup for A Level Mathematics -- 3 of the 6 ECR files were filed under the wrong component. These files carry the OLD pre-2020 9709 paper numbering (M1/M2/S1/S2 as separate papers 4-7), which does not line up 1:1 with the current 6-paper numbering (Mechanics merged into one Paper 4). Caught by actually reading each file's content, not trusting the cover label: the file labeled "Paper 5" contained mechanics content ("centre of mass of a semi-circular lamina") but was filed under "Probability & Statistics 1"; the file labeled "Paper 6" contained permutation/combination with no hypothesis-testing (real S1 content) but was filed under "Probability & Statistics 2"; the file labeled "Paper 7" contained null/alternative hypothesis and z-value testing (real S2 content) but had been added as a second document on the wrong component. Now: Paper 4 (Mechanics) has both the old M1 and M2 documents, Paper 5 (S1) and Paper 6 (S2) each have their correct single document.

* **mcq-digitizer:** grading was very slow and sometimes hit the 85s deadline. Cause: Gemini returned 429 (real account quota, not our own RPM self-throttle) dozens of times a minute apart on 2026-09-22, and each grading call kept re-trying and re-waiting on the same quota-exhausted model before falling back. A model that returns 429 is now skipped for 3 minutes so the next call goes straight to the next model or OpenRouter. Verified live: a grading call now completes in 14-15s instead of timing out.

* **mcq-digitizer:** written-answer grading now runs as a background job. "Submit answer" starts a job (`POST /api/grade-structured-question` with `async: true` returns a job id) and the page shows "Grading… Ns" while it checks `GET /api/grade-structured-status` every 2 seconds, so no single request has to survive the tunnel's ~100 second limit when the AI provider is slow. Jobs expire after 15 minutes; a job that takes over 5 minutes reports an error. Tested through the live site and in a browser.

* **mcq-digitizer:** "Couldn't submit: Extraction service returned an invalid response" when submitting a written answer. Causes found: (1) grading sometimes ran past ~100s, when the Cloudflare tunnel cuts the connection and returns an HTML page the site cannot read; (2) two of the three Gemini models in the grading pool (`gemini-2.5-flash`, `gemini-2.5-pro`) now answer 404 "no longer available", and `gemini-3.5-flash` often answers 429 quota; (3) the first submit on a yearly paper re-ran the Python extractor. Now: the pool is `gemini-3.5-flash` + `gemini-3-flash-preview`; a 503 "high demand" is retried once on the same model; per-attempt timeout is 40s; grading answers with a clear "taking too long, press Submit answer again" JSON message after 85s instead of letting the tunnel cut it; the yearly digitize result is cached (20 papers) and shared with grading; the site shows "Question Solver did not answer properly (it may be restarting or busy). Wait a minute and try again." instead of "invalid response". Still open: when Google is slow or over quota, about one grading call in three can still fail after 85s.

* **mcq-digitizer:** subjective answers (English summaries, letters, articles, notes, forms) now graded by applying the mark scheme rubric. (1) Total marks come from the scheme's "Max total for Exercise N: X marks" line, or the question paper's "up to N marks for content ... and N for language". (2) A scheme block that is only a heading (Exercise 6, which shares Exercise 7's criteria table) borrows the next block's criteria image. (3) The question paper's task text is sent to the grader, so a letter is marked against the letter task, not a neighbouring exercise (the first test marked a letter down as off-topic before this). (4) The grading prompt now tells the model to score each criterion (Content, Language) separately with its band, award one mark per distinct content point, apply word-limit penalties, and write a sample top-band answer. Marks also read from "Max overall total for exercise N: X marks" and "[Total: N]" (other years print marks that way), and the heading-only borrow applies only to writing tasks, so Listening's short answer blocks keep their own scheme. Marks now resolve for all 1,072 questions across the 152 English Reading and Writing / Listening papers from 2014 to 2026 (63 were missing before this). Tested on English Reading and Writing 0510_s14_21: good summary 10/11, one-line summary 0/11, letter 11/19 (under the word limit), article 12/19, form 4/8. Each grading call takes 30 to 110 seconds.

* **mcq-digitizer (TKT-0270):** yearly past paper Test attempts showed "No questions attempted" with every question "Not auto-gradable". Official yearly mark schemes list marks as bare numbers in a table, so the mark count read from the mark scheme was 0 for every Physics/Chemistry Theory question, every Mathematics question, and most Listening questions. The grader now falls back to the `[N]` marks printed in the question paper. Per-paper question totals match the real paper totals (Physics 80, Chemistry 80, Mathematics Paper 2 70, Paper 4 130). English Reading and Writing questions 3 to 7 (writing exercises marked by criteria, not `[N]`) are still not auto-gradable.

* **site (TKT-0262):** pages showed completely unstyled on older Safari (macOS Big Sur and earlier, iOS 15.3 and older). Tailwind v4 puts about 77% of the site CSS inside `@layer` blocks, which those browsers ignore entirely. The build now flattens the layers (`@csstools/postcss-cascade-layers` after Tailwind in `postcss.config.mjs`), so the built stylesheet has no `@layer`. Checked in Chromium against production: home (only the background video frame differs), pricing and login render identically. Not yet checked on a real old Safari.

* **mcq-digitizer (TKT-0268):** "Submit answer" on a yearly past paper in Test mode failed with "qpId, msId, and questionNumber are required." The grader only understood topical worksheet ids. `POST /api/grade-structured-question` now also accepts a yearly `paperId`; the server crops that paper's own mark scheme (cached per paper) and grades against it, the same way as topical papers. Live-tested on a yearly English paper (9 marks, full breakdown returned) and a topical paper (unchanged).

* **mcq-digitizer (TKT-0267):** removed the header line "question paper + mark scheme → instant multiple-choice quiz. No LLM, anywhere." It was wrong: structured-question grading uses an AI model.

* **mcq-digitizer, syllabus-digitizer:** UI-copy cleanup across both tools' progress/leaderboard/mode-select screens. (1) Removed parenthetical asides from hint text (e.g. "(attempts/questions answered)", "(no content text under this heading)") in favor of plain sentences. (2) A leaderboard section title had a full explanatory sentence wedged into a bold/uppercase/small title style, rendering as an oversized wall of text instead of a short label -- shortened back to "By volume", matching its siblings ("By average score", "By total correct"). (3) Removed every remaining stylistic em dash from authored UI text (kept the "--" glyph only where it's a genuine no-data table placeholder, a different, pre-existing convention). (4) The Practice/Test mode buttons on both the MCQ and structured-paper flows had full explanatory sentences as their button label ("Practice mode: browse freely, no grading") -- split into a short button label ("Practice Mode") plus a small caption underneath, since a button states an action, not an explanation.

* **mcq-digitizer (TKT-0257):** three separate ordering/visibility bugs reported as "answers aren't organized correctly in attempt history and corrections are not visible." (1) The attempt-history "View" panel now shows the actual question image on demand (separate "View QP"/"View MS" buttons), the correct answer when a student got a question wrong, and a flagged-for-review badge -- none of this was visible before. (2) Per-question answers in that same panel were ordered by a text sort on `question_number` (a DB column that's always a string), producing "1, 10, 11, 2, 20, 3..." on any paper past 9 questions -- now sorted numerically (`naturalQuestionSort`), also handling compound labels like "1a"/"10b" for structured papers. (3) The worksheet picker's "Paper" dropdown had the same root problem one level up: papers were listed in whatever order the Drive crawl produced, not chapter order -- confirmed on real data (A Levels Chemistry's crawl left "8.2", "22-alkenes", and "29.1" stranded at the end of the list instead of next to "8.1", between "21"/"23", and next to "29.2"). Now sorted by (chapter number, worksheet number, title).

* **mcq-digitizer (TKT-0258):** chapter *names* (not just numbers) were missing from the mistake-history chart and leaderboard for every Mathematics paper, and -- found while fixing this -- every Physics/Chemistry/Biology Theory paper too (283 titles total). The name-extraction regex only recognized the `(MCQ)` title format; these subjects use a different convention (`ChN Topic Name (Paper/Theory) Worksheet N`) that silently fell back to showing a bare chapter number with no name. Added a third pattern covering all 874 structured-library titles.

* **resources:** Syllabus Viewer link now carries `?account=&name=` like Question Solver already did, so its own "My progress & leaderboard" feature is actually reachable instead of permanently hidden behind a `display:none` link nobody could unlock.

* **mcq-digitizer (TKT-0260):** the entire yearly-past-papers feature -- every subject, not just English -- was completely unreachable in production: `GET /api/yearly-library` and every route downstream of it returned a bare "Not found". Root cause, confirmed live: the standalone Node process serving it (`prototypes/mcq-digitizer/server.mjs`, port 5178) had been running continuously since 2026-09-17 04:36, a full day before the yearly-papers feature was even added to the codebase (first commit 2026-09-18), and had never been restarted since -- Node loads the whole file into memory at process start and never hot-reloads, so a `git commit` (including yesterday's TKT-0251 yearly-MCQ auto-grading fix, `cfee476`) never reached the live process no matter how long it sat merged. Reported by a user asking "why does English not work" -- English's "Paper 2: Reading and Writing (Extended)" was simply the specific case they hit; every other subject's yearly papers were equally down. Fixed 2026-09-20 by restarting the process (no code change needed -- the fix was already on disk, just never loaded). Live-verified post-restart: `GET /api/yearly-library` now returns 200 with English's real components, and a real 2014 English yearly paper (`0510_s14_21`) digitizes correctly (7 questions extracted).

* **mcq-digitizer:** fixed two per-question splitter bugs found by auditing all 391 Mathematics Paper 2/Paper 4 worksheets for atomicity. (1) Some mark schemes carry a duplicate "Question N" heading at the exact same position as the real one, mislabeled one number too high -- the browser's `find()` silently paired every even-numbered question with a near-blank duplicate crop instead of its real mark scheme. (2) Some multi-page questions repeat their own "Question N" heading on the continuation page, which the splitter mistook for a second question, splitting one question into two. Also fixed a font-encoding variant (`\x03` used as inter-word spacing instead of a real space) that made 4 worksheets fail to split at all. All 391 papers now split atomically, verified by a full-corpus recheck.

* **mcq-digitizer (TKT-0243):** a Test-mode attempt's `totalQuestions` sent to the progress tracker/leaderboard counted every question in the paper that had a real answer key, whether the student actually answered it or not -- opening a 10-question paper and answering only 5 recorded totalQuestions=10, inflating the denominator with questions never attempted. Now counts only the questions actually answered (MCQ) or actually submitted (structured). The on-screen score shown immediately after submitting is unaffected -- this only changes what gets persisted to history/leaderboard.

* **mcq-digitizer (TKT-0244):** the attempt-history table showed a raw Google Drive file id instead of a readable worksheet title whenever a past attempt's subject fell outside the student's current enrollment -- `paperTitleById` was built only from the enrollment-filtered library response. Added `GET /api/mcq/paper-titles`, a title-only lookup deliberately NOT filtered by live enrollment (a past attempt's paper name isn't a "what can this student browse" question), which now backfills any gap in the title map.

* **mcq-digitizer:** an active Practice/Test/Mistakes-mode session had no way to cancel and return to the library other than a "Back to library" link at the very top of the page (MCQ's own quiz header had no back-navigation at all). Added a "Cancel" button next to the Pause/Resume timer control in both the MCQ and structured-paper quiz headers -- confirms first in Test/Mistakes mode (where cancelling discards in-progress answers), leaves immediately in Practice mode (nothing to lose, never graded).

* **resources:** Syllabus Viewer's link had gone dead -- its standalone server and Cloudflare tunnel (a separate always-on process this hardcoded URL points at, unlike Question Solver's which is DB-config-driven) were not running at all. Restarted both and updated the hardcoded URL to the new tunnel. Confirmed via Vercel runtime logs this was not a platform/env-var issue -- no env var drives this URL anywhere, the latest deployment was healthy, and the one runtime error in the last 24h was a single transient timing blip during the Question Solver tunnel's own restart, not a recurring fault.
