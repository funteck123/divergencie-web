# Changelog

All notable changes to this project are documented here. Format loosely
follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions
follow [SemVer](https://semver.org/). This project is pre-1.0 (alpha) —
expect breaking changes between minor versions. Version bumps and this file
are generated by [commit-and-tag-version](https://github.com/absolute-version/commit-and-tag-version)
(`npm run release`) from Conventional Commits — see `CONTRIBUTING.md`.

## [Unreleased]

### Changed
- **TKT-0003**: Invoices are now billed month-wise, not subject-wise — one
  combined Invoice per student per month (Monthly/Hourly-billed subjects),
  with an itemized LineItems breakdown per subject. OneOff-billed invoices
  (books, admissions, etc.) are unaffected — still one standalone invoice
  ever, unrelated to a specific month.
- Invoice totals shown to Students/Parents are now in the student's own
  profile currency (converted + locked at generation, same convention as
  the existing INR conversion); Management's Billing view still shows an
  INR column for internal accounting.
- Mid-month enrollment start/end dates now prorate billed hours correctly
  (previously an enrollment starting partway through a month was billed
  for the whole month's scheduled hours).
- Paychecks now mirror the same month-wise billing as Invoices — one
  combined Paycheck per staff member per month (Monthly/Hourly-billed
  services), itemized LineItems breakdown, OneOff paychecks unaffected.
  Payslip PDFs are itemized per subject with correct Gross/Nett Pay and
  Employer SOCSO across the combined total. New
  `POST /api/paychecks/migrate-monthly` (same dry-run-by-default,
  backup-snapshot pattern as the invoice migration) folds existing
  per-subject paychecks into the new shape. Also fixes a pre-existing
  bug where a freshly generated paycheck's INR Due was always 0 instead
  of the full amount owed (Amount Due showed "nothing owed" on a
  brand-new unpaid paycheck).
- Invoice PDFs are now one per student per month, itemized per subject.
- **TKT-0013**: Manual invoice creation is now month-wise, not one service
  at a time — pick a student and month, get a checklist of every subject
  they're currently enrolled in (all pre-checked by default), type an
  amount per checked subject, submit once to create/append all of them.

### Added
- **TKT-0015**: The Enrollments tab's enroll form can now mint a one-off
  custom Rate inline, per service row ("+ New rate for this service"),
  instead of being limited to a Service's already-defined Rates — new
  `POST /api/services/rates` appends one Rate to an existing Batch (or a
  role-based Service's own Rates list) without resending the whole Service.
- Ticket # is now shown as its own column on the admin Tickets tab.
- The Worksheets resource page now auto-lists a Google Drive folder's
  contents as clickable cards (each opening its own file directly) when
  WorksheetsLink is a Drive folder link, alongside the existing "Access
  Worksheets" button — new `GET /api/resources/drive-folder`. Requires
  `GOOGLE_DRIVE_API_KEY` to be set; the target folder must be shared
  "Anyone with the link", same assumption the existing link already makes.
- `POST /api/invoices/migrate-monthly` — one-time migration folding
  existing per-subject invoices into the new combined-per-month shape.
  Dry-run by default (`{ apply: true }` required to write); dry-run
  response includes a full pre-migration backup snapshot.
- **TKT-0004**: Student accounts now have an optional Parent Email field
  (Management-only edit), alongside the existing Parent WhatsApp Number.
- **TKT-0005**: Bulk-enroll a single student into several services at once
  from the Enrollments tab, sharing one Start/End date across the batch.
  Redesigned into the existing single-enroll form itself (repeatable
  "+ Add another service" rows, each with its own Batch/Rate picker)
  instead of a separate Bulk Enroll box.
- **TKT-0006**: Search box on the Services tab, filtering by name.
- **TKT-0007**: Standardized all date displays across the app to
  DD/MM/YYYY (DD/MM/YYYY, HH:MM for timestamps) via a shared
  `lib/formatDate.js` utility — schedule/attendance tables on every
  dashboard, reschedule requests, enrollment Start/End dates, audit
  log and ticket timestamps, and invoice/paycheck PDFs. Date *inputs*
  are unaffected (native `<input type="date">` is always internally
  yyyy-mm-dd regardless of display format) — this is display-only.
- **TKT-0008**: Fixed the Schedule Image — Student header now shows the
  student's own Course field (e.g. "IGCSE") instead of a blank slot.
  Each occurrence's Day/Time is now converted from the timezone it was
  actually scheduled in into the viewing user's own profile timezone,
  so displayed times genuinely match the timezone printed in the
  header — previously the raw stored time was shown as-is, mislabeled
  under the viewer's timezone even when the occurrence was set in a
  different one (`lib/timezones.js`'s new `convertWeeklyTime`, using
  `Intl.DateTimeFormat` — correctly handles DST).

### Fixed
- `allowedDevOrigins` now also matches `*.trycloudflare.com` — viewing the
  dev server through a `cloudflared tunnel --url` quick tunnel had Next.js
  blocking cross-origin dev requests, so client JS never hydrated. SSR
  HTML still rendered fine, but anything gated behind a client-only mount
  (Nav — hidden until mounted, to avoid a theme/scroll hydration mismatch)
  stayed permanently invisible, making the nav bar appear "missing" on the
  home page when viewed through the tunnel.
- Code review finding: `generate` could create a duplicate invoice for a
  student/month that was already billed under the pre-rewrite flat shape
  but hadn't gone through `migrate-monthly` yet — now skipped, same as
  any other already-generated line item.
- Management's Billing view now shows a non-blocking warning (⚠ dup?)
  on any student/month with more than one invoice, with a recommendation
  to delete the duplicate if it's genuinely double-billing the same
  subjects — doesn't block creation, since a real OneOff purchase can
  legitimately coexist with a combined invoice in the same month.
- Schedule Image: every grid cell was filled with the role's color
  (blue/green/amber) regardless of whether a class was actually
  scheduled there, making an empty week look identical to a fully
  booked one. Now only cells with an actual class are colored;
  everything else is plain white. Found during manual testing of
  TKT-0008 (`lib/scheduleImage.js`'s `drawSchedule`, unrelated to the
  earlier label/timezone fix in that same ticket).

## [0.1.1](https://github.com/funteck123/divergencie-web/compare/v0.1.0...v0.1.1) (2026-07-30)

### Added
- Automated versioning/changelog via `commit-and-tag-version` (`npm run
  release`) — computes the next SemVer version and rewrites this file from
  Conventional Commits, commits and tags locally, but never pushes; push
  stays a deliberate manual step since it triggers Vercel's production deploy.
- Error monitoring via Sentry (server + client instrumentation), tuned for
  free-tier usage: low trace sampling (5%), 404s and browser-extension noise
  filtered out before they count against quota.
- Management audit trail (`auditlog` table) — every mutating admin action
  (services, users, invoices, paychecks, enrollments, reschedule approvals,
  API keys, ticket close/reopen) now records who did what, when.
- App-level structured logging (`applogs` table) alongside the audit trail.
- Generic issue-reporting Tickets feature: any signed-in account can raise a
  ticket (message + optional attachment URL) via a "Report an issue" button
  on every dashboard; Management can view, close, and reopen tickets from a
  new Tickets tab.

### Fixed
- `$0`-total invoice warning now only fires when it's actually misleading.
- Reschedule-request approval closed an IDOR (a non-owner could act on
  someone else's request).

### Notes
- This release also ships the full backlog of commits from Jul 19 onward
  that had never been pushed to `origin/main` before now — see `git log`
  for the complete list; only the changes above were made in the session
  that added this changelog and the tickets/monitoring features.
